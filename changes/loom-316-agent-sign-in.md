### Added

- Agent sign-in (LOOM-316, #555): when an agent CLI on a target isn't signed in, Loomux opens the CLI's own login (`claude auth login`, `codex login --device-auth`) in a tmux session there and gives the exact attach command; the person signs in by attaching, and Loomux never types into, reads or completes that session. A dispatch whose pre-launch probe finds the agent signed out (and no API key for it in the vault) now fails at once with `login_required` naming that session, instead of launching an agent that can only stop at its sign-in screen. `POST`/`DELETE /api/v1/targets/{id}/agents/{agent_type}/sign-in` open and close it.
- Agent auth status (LOOM-316): `GET /api/v1/targets/{id}/agents` (and the probe's response) gives each agent an `auth` block: `state` (`logged_in`, `logged_out`, `expired`, `rate_limited`, `unknown`), the sign-in method, plan and expiry the CLI reports (allow-listed words only, never the account's email), the sign-in problem or usage limit a turn last hit, and the open sign-in session with its attach commands. `loomuxd agents status` and `loomuxd agents sign-in` are a command-line client of these routes.
