### Security

- A vault credential's ciphertext is bound to its scope as well as its row (LOOM-192): the AES-GCM additional data now names the row's workspace, target and agent type, so a credential moved to another workspace, target or agent type (or from unscoped to scoped) by someone with write access to the database but not the key no longer decrypts there. Migration 00031 renames `sealed_to_id` to `seal_version` and adds `vault_reseal`; the first start with `LOOMUX_MASTER_KEY` re-seals the existing rows in one transaction and records the re-seal as done, so later starts don't scan the vault again. If any row doesn't open under the configured key, nothing is recorded and the next start tries again. A release from before this can't read re-sealed rows: roll back with the pre-upgrade snapshot.
