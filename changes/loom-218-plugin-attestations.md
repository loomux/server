### Security

- A plugin from the plugin directory (`LOOMUX_PLUGIN_DIR`), which runs as loomuxd's own user, is installed, upgraded to and started only when something vouches for its executable (LOOM-218). Either its sha256 is pinned in `LOOMUX_PLUGIN_DIGESTS`, or a Sigstore bundle beside it (`loomux-plugin-<name>.sigstore.json`) holds SLSA v1 build provenance for it, signed by a GitHub Actions workflow listed in `LOOMUX_PLUGIN_SIGNERS`. The bundle is checked against `LOOMUX_PLUGIN_TRUSTED_ROOT`, or Sigstore's public-good root via TUF. Otherwise install and upgrade answer `422` with the reason. An installed plugin whose executable no longer verifies is refused at start, and its machines keep working. `LOOMUX_PLUGIN_ALLOW_UNSIGNED=true` turns the requirement off for local development. Bundled plugins and sidecars are unaffected.
