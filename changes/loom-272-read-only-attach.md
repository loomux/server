### Added

- Read-only attach commands for a watch (LOOM-272, the terminal client's S11). A takeover with `mode: "watch"` now answers with commands that attach read-only, with tmux's `-r`, so a person who only watches can't type into the pane: `attach_command` is `tmux -L <socket> attach -r -t <session>`, the ssh entry of `attach_commands` runs that line on the target, and a Kubernetes or Docker machine's entry is the plugin's `kubectl exec` / `docker exec` form around it. The server builds or checks every one; the writable commands of attach-info are never in a watch's answer. On tmux 3.2 or later `-r` also keeps the watcher's terminal from resizing the window.
- `409` with code `watch_unsupported` from `POST /api/v1/tasks/{id}/takeover` with `mode: "watch"`, when the task's target is a machine whose plugin has no read-only attach command. No hold is taken and no writable command is handed out instead. The message names the plugin.
- Plugin protocol: `targets.attach_commands` takes `read_only` and its result confirms it with `read_only` (LOOM-272), under the new manifest capability `targets.attach_read_only`. The host asks only a plugin that declares it, uses only a confirmed answer, and keeps only commands whose `argv` has `-r` directly after tmux's `attach`. In the SDK the read-only commands are `sdk.ReadOnlyAttacher`; a plugin without it fails a `read_only` call rather than answer with its writable commands. The Kubernetes and Docker plugins implement it.

### Changed

- The Kubernetes and Docker plugins' manifests declare `targets.attach_read_only` (LOOM-272). This is a capability change: update the server before the plugins (an older server refuses a manifest that declares a capability it doesn't know), and upgrade each installed instance of the two plugins once afterwards. A plugin whose capabilities changed isn't adopted to the new version by itself and shows `error` ("changed its capabilities or configuration schema; upgrade the plugin") until then.
